02 Сквозная схема решения

on-chain off-chain threshold evidence
1

Tribute → sealed root

CE end-block: body commitment → 16 shards → WWD collection → CE catalog → EVM slot → finalized state root.

2

Metadosis делит budget

day_limit = lysis_budget + auction_base. GREEN сразу отправляет auction_base в Desis; RED — в carry-over. Затем сохраняются JobIntent(lysis_budget), job AWAITING_FINALITY и day OFFCHAIN_PENDING.

3

Finality + 4 открывает voting

JobId связывает intent с request block/state root. Через 4 блока consensus фиксирует VOTING_OPEN(open_height, deadline_height).

4

Deterministic execution

Полный CE fold, Fidelity/Oracle openings, fixed UnitId, Map/Reduce. 1, 2 и 4 workers дают одинаковые bytes.

5

Full-result validator votes

Каждый domain сам вычисляет весь job. Node подписывает canonical LysisResultV1 и его binding, а Supervisor отправляет validator-only ZeroFee EVM tx напрямую в blockchain. В state слот хранит только digest, signature и inclusion height.

6

Third vote applies

Транзакция, создающая q=3, сохраняет canonical result один раз и под тем же outer checkpoint применяет roots/scalars. Отдельного relay, activator или activation transaction нет; Lysis on-chain не считается.

7

Atomic domain effects

Nod + contributors + Tribute retirement + unused-Lysis carry-over + Metadosis COMPLETED + ActiveGenerationV1. Desis здесь не вызывается; поздний 4th vote меняет только отдельный accountability record.

03 Что именно доказывает PoC

Это проверка core-механики, а не заявление о production readiness или масштабе.

PoC доказывает

  • finalized/authenticated input
  • deterministic parallel execution
  • 3-of-4 independent result threshold
  • Supervisor → ZeroFee vote → on-chain slots
  • sign-once и exact result binding
  • one-tx atomic typed apply
  • supervisor failure не убивает node

PoC сознательно не включает

  • 1B / TargetLarge / scale claim
  • recursive proof и counted range tree
  • DA, custody, witness state, claims
  • HSM, mTLS и production launch broker
  • supported-network migration/upgrade
  • production SLO / chaos / recovery gate
  • generic registry/envelopes и второй program

Failure semantics

  • 1 domain offline: q=3 работает
  • 2 domains offline: job expires
  • 4th missing: canonical accountability evidence
  • 4th after quorum apply: terminal identity unchanged
  • double vote: equivocation evidence
  • bad result: reject, no state change
  • write conflict: CONFLICTED → READY
  • no supervisors: expiry всё равно on-chain
  • никогда: synchronous fallback
