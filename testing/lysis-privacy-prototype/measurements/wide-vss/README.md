# P-384 Pedersen VSS: один денежный агрегат

Дата измерений: 2026-09-11. Это отдельный компонентный прототип для T03, а не новый полный Tribute proof. [Исходный код](src/main.rs), [результаты](results.json), [provenance](provenance.json), [контракт хранения](../../STORAGE_AND_AGGREGATE_PROTOCOL.md), [первоисточники и ограничения](../../WIDE_FIELD_VSS_RESEARCH.md).

## Что выполнено

Пользовательская сторона создаёт Pedersen commitment C(a)=aG+rH и два полинома степени t−1 над scalar field P-384. Участники проверяют свои пары долей по публичным commitments коэффициентов. Проверенные shares складываются. Старые участники передают новый sharing того же агрегата; затем t проверяемых суммарных вкладов позволяют восстановить S и случайный aggregate blinding R.

**Публичный денежный результат — одна сумма S, без четырёх сумм частей uint256.** Открывающие вклады также раскрывают случайные коэффициенты агрегатных полиномов. Произвольные индивидуальные amounts для этого открывать не требуется. Пороговое предположение и корректность admission обязательны; проверка source/range proof здесь отсутствует.

Порядок группы q имеет 384 бита и превышает 10⁹·(2²⁵⁶−1), занимающее 286 бит. Это scalar order, не модуль координат кривой. H получен через hash-to-curve RFC 9380; строка domain separation и encoded point находятся в JSON. Параметры имеют исследовательский context и не являются закреплёнными параметрами production.

## Воспроизведение

Из корня репозитория, с уже закешированными зависимостями:

~~~sh
cargo run --offline --locked --release --manifest-path testing/lysis-privacy-prototype/measurements/wide-vss/Cargo.toml > /tmp/outbe-wide-vss-results.json
cargo fmt --check --manifest-path testing/lysis-privacy-prototype/measurements/wide-vss/Cargo.toml
~~~

Самостоятельный Cargo workspace; RustCrypto p384 0.13.1, sha2 0.10.9, точные зависимости в Cargo.lock. Apple M4 Max, 14 ядер (10P+4E), 36 GB RAM, macOS arm64; rustc 1.96.0. Все роли выполняются последовательно в одном процессе, CPU не изолирован. Seed fixture фиксирован: этот исполняемый файл нельзя использовать для реальных секретов.

## Измеренные компоненты

Для deal/check/open: один прогрев, затем медиана четырёх образцов. Deal включает оба полинома, публичные coefficients и shares всех n получателей. Проверка — одна share-pair одного получателя. Opening включает проверку каждой из t contribution pairs, интерполяцию и финальную commitment equation. Это не latency сети.

| n / t | Пользователь: deal всем n, мс | Получатель: проверить свою пару, мс | Нода: проверить t вкладов и открыть S, мс |
|---|---:|---:|---:|
| 16 / 6 | 3.193 | 0.579 | 4.390 |
| 16 / 11 | 5.758 | 0.589 | 7.543 |
| 128 / 43 | 22.868 | 0.776 | 36.842 |

Handoff измерен отдельно **одним образцом**: вся последовательная работа t старых dealers и всех n новых получателей, включая проверки, без сети. Финальное opening нового sharing проверяется после таймера.

| Handoff | Время, мс | Private payload всем новым получателям | Публичные coefficients всех dealers |
|---|---:|---:|---:|
| 16/6 → 16/6 | 80.778 | 9,216 B | 1,764 B |
| 16/11 → 16/11 | 180.239 | 16,896 B | 5,929 B |
| 128/43 → 128/43 | Не измерено | — | — |

Это передача **одного агрегата**, а не миллиарда индивидуальных записей для поздней группировки. Из этих замеров нельзя получить end-to-end Tribute/s: source/range/arithmetic proof теперь измеряется отдельным [P_link](../p-link/README.md); интеграция с L2 admission и сетевой VSS availability ещё не выполнена. Старые Ristretto proof timings и 0.126 мс limb opening относятся к другому представлению и набору проверок.

## Сырые размеры

Scalar — 48 B, обычная compressed point — 49 B, секретная пара — 96 B. Identity требует отдельного canonical wire rule; здесь размеры point slots рассчитаны как 49 B. Метаданные, подписи, индексы, WAL, proofs и репликация не включены.

| n / t | VSS coefficients одного входа, включая C(a) | Дополнительно к уже имеющемуся C(a) | Private fanout всем n | Открывающие t пары |
|---|---:|---:|---:|---:|
| 16 / 6 | 294 B | 245 B | 1,536 B | 576 B |
| 16 / 11 | 539 B | 490 B | 1,536 B | 1,056 B |
| 128 / 43 | 2,107 B | 2,058 B | 12,288 B | 4,128 B |

Собственный секретный накопитель участника — 96 B **на заранее определённую группу**. При поздних лигах нужны индивидуальные записи: для 1 млрд это 96 GB private payload на участника и при t=6 ещё 294 GB публичных current coefficient vectors в одной копии DA. Последние нужны для проверяемой передачи индивидуальных shares при ротации; это не исторический объём всех версий.

## Что проверяют assertions

- Uint256::MAX проходит scalar roundtrip без modular reduction.
- Два независимых больших значения складываются и точно открываются вместе с aggregate blinding.
- Плохая доля, неверный context, повторная координата участника и недостаток вкладов отвергаются; неверная заявленная сумма не проходит commitment equation.
- Reshare сохраняет весь secret pair и исходный commitment; старый share не проходит проверку относительно нового sharing.
- Sharing uint256::MAX умножен на 10⁹ и открыт как точное 286-битное целое. **Это проверка вместимости поля, не обработка миллиарда входов.** Если протокол ограничивает итог uint256, такой итог должен быть отклонён; соответствующий флаг есть в JSON.

Функция переменного времени используется только для умножения публичной точки на публичную малую координату получателя. Секретные scalar multiplications выполняет библиотека. Собственная композиция протокола не проходила аудит.

## Что ещё не реализовано

- Production admission с проверкой существующего P_L2 и нового [P_link](../p-link/README.md), связывающего source/range/arithmetic с **этим же P-384 commitment**. P_link добавлен отдельным компонентом. Одна VSS equation по-прежнему не доказывает диапазон или происхождение nominal.
- Подписи, confidential transport, сетевые receipts, общий accepted root и общий набор Q с полным состоянием. Поле context в локальном коде не доказывает его связь с accepted inputs.
- Consensus/handoff при отказах и злонамеренной сети, durable storage, crash recovery, безопасное удаление старых секретов и защита от накопления компрометаций.
- Передача индивидуальных записей поздних лиг, приватные PayNote/Fidelity и exact claim proof 6→18.

В JSON `own_share_acknowledgments_needed_without_repair=t+f` — необходимое количество receipts для одной записи в простой модели. Меняющийся набор такого размера **не гарантирует** общий полный накопитель для всех записей. Проект с фиксированным обязательным Q и паузой/handoff при его отказе описан в контракте хранения; в этом executable его нет.
