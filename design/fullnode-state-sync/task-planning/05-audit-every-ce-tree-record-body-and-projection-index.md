## Implementation

1. Current source and input-sufficiency evidence: design/fullnode-state-sync/validation-audit.md and data-layout.md; current task clauses incorporate the audit corrections. Existing API names are evidence; proposed new owner APIs are concrete implementation requirements, not already implemented features.
2. Keep complete CE verification inside crates/core/compressed-entities so private CeMetadata/CeTreeRoots/CeLeaves/CeBranches and native namespace/field/branch codecs are reused. CeMdbxReadOnly::open/open_exact only prove point identity and root metadata; full audit_exact must enumerate all rows under one RO transaction, bind required ExactParentIdentity, reject malformed or unknown schema/key/namespace/field encodings, and never create/recover the source environment.
3. Define CeAuditVisitor::visit_leaf(&mut self, namespace: TreeNamespace, key: TreeKey, value: LeafValue)->Result<(),CeAuditError>; callback errors terminate verification. Emit every validated live and catalog leaf once, with bounded per-call values. CeBodyAudit::create(work) implements this visitor to persist expected shard leaves/catalog identities in scratch, then accepts push_body(domain:CeDomain,id:WwdEntityId,encoded:&[u8])->Result<(),CeAuditError> and finish()->Result<CeBodyAuditReport,CeAuditError>. This explicit route exposes bounded enumeration without requiring a whole-dataset Vec or raw DB access.
4. Rebuild each tree from its leaf inventory using native PoseidonSmt and a scratch-backed CKB store starting at zero root. Compare the entire generated branch-key/value set with persisted branches in both directions, catching missing, changed and unreachable extra records; compare native root rows as well. Use external sorted runs where ordering is needed and native TreeKey::Ord (CKB reversed-byte numeric order), not raw MDBX lexicographic ordering. Reuse native codecs/Poseidon/collection/shard combiners; introduce no copied cryptographic recipe.
5. Apply exact native collection representation: absent collection has no catalog leaf and no root/branch/leaf rows. A materialized collection has a catalog leaf and exactly K explicit root rows, currently16, including zero roots of empty shards. read_collection_roots accepts only zero records as None or all expected K records; temporary ZERO fallback is not permission for a partial sparse set. A zero-body materialized collection can remain present with its nonzero domain-separated collection root. Retirement removes its catalog leaf and every collection record. Catalog has its own explicit root row; zero root/no catalog leaves is valid empty catalog, missing root row is corruption.
6. For materialized collections recompute each shard root, aggregate native shard roots, recompute collection_root and compare the catalog commitment. Match catalog and collection populations both directions, recompute catalog tree and sealed_root, then compare marker and exact canonical header CE artifact from task04. Body-derived domain/WWD identities map hashes to actual collections; do not claim to invert a hashed collection key. For Q=0 apply the native genesis identity/empty catalog/sealed_root(ZERO) rule explicitly; do not call the point-proof helper that rejects block0.
7. CeBodyAudit::push_body uses existing canonical_body_leaf made crate-visible: StoredBody::decode, domain decoder, exact body-ID match, active-scheme body_commitment. Derive collection key/shard/tree key with native CE functions and external-sort tuples. finish merge-joins all derived body tuples against all expected live CE leaves: exactly one matching body per leaf, no extra primary bodies or duplicate identities. Body-scan absence must not be hidden by relying on a secondary index. This commits canonical body identity/payload, not provenance block/tx/log/emitter metadata. Metadata gets native encoding checks only; do not claim event provenance authentication.
8. Tribute/Nod repository scans use bounded ScanRequest/IdPageRequest with strictly increasing exclusive cursors and return canonical key/body pairs. Scan Tribute primary tributes, Nod primary nods and separate nod_buckets. audit_indexes traverses primary and every native owner/day index in both directions, using owner codecs and scratch merge sets to reject missing/dangling/wrong-owner/wrong-day entries. Preserve current namespace/schema ownership and do not change projection writers.
9. Read projection with RocksDbReader::open(primary, external_disjoint_secondary) and existing read_projection_state. Full live CE/body equality is checked only at the same actual block identity Q=P; unequal progress is an explicit incomplete equality result, not a synthetic cursor rewrite or a failure of cheap creation. No historical body reconstruction is invented. All scratch buffers/pages have checked limits; large populations spill rather than consume unbounded memory. A normal stopped donor makes these stores stable, not necessarily equal. Still emit independent CE structural and projection/index results on Q!=P; equality remains Incomplete and selected all mode cannot flatten it into Passed.
10. Retained Tribute is separate from live CE. Add a bounded visitor that enumerates both ocomp_retained_tributes and ocomp_retained_tributes_by_day with native RetainedTributePin/RetainedTributeRef selectors and canonical stored body, checking both directions. Task06 applies pin-state obligations and historical partition authority. Existing RetainedTributeReader::list_by_day/get_current_or_retained remain available, but cannot prove absence of orphan primary rows by themselves.
11. For each complete still-required Tribute partition selected by task06, use BoundedTributePartitionVerifier::{create,push,finish} with canonical JobIntent sealed_tribute_collection_key/root, authenticated_day_count, WWD and native scheme. Task06 binds immutable intent/lease/finality from current E plus retained B header. CandidatePin.ce_sealed_root is a catalog-wide commitment, not this partition root. Select/deduplicate the native live-or-retained union. GcPending may have partial or empty residuals; check surviving row/index consistency, not a deleted full partition. Released/pruned jobs require no historical body population; evaluate shared live leases before relaxing an obligation.

## Tests first

1. Owner-internal RED fixtures: alter leaf while preserving stored root/marker; alter branch; add unreachable branch; remove catalog root; malformed namespace/field and wrong shard; substitute catalog leaf. Full audit must fail even if cheap open still passes.
2. Representation tests distinguish valid genesis with no collections, present materialized collection with explicit K roots and zero empty shards, materialized zero-leaf collection, K-1 roots with omitted zero shard (invalid), fully absent/retired collection (valid), and absent catalog leaf with residual collection root/branch/leaf (invalid).
3. Run-boundary tests use tree keys whose native order differs from lexicographic order, duplicate keys across sorted runs, bounded spill/merge and visitor failure. Assert every expected leaf is emitted exactly once and memory retention stays within configured page/run bounds.
4. Public body API tests delete one committed primary body, add an uncommitted primary body, change well-formed body ID/payload, use unsupported StoredBody schema, and omit a bucket that an item-only scan would miss. Each has a specific non-success result.
5. Primary/index tests remove one index, create dangling index, change owner/day or retained commitment/lease key, and exercise pagination at exact boundary/last page. Complete primary traversal catches data omitted from damaged indexes.
6. Multi-collection nonzero fixture includes Tribute days, Nod items/buckets and retained old Tribute. Q=P passes live equality; Q!=P is explicit incomplete without mutation; valid old retained body absent from live CE is accepted as a separate population for task06.
7. Source contents/membership/protected sentinels remain unchanged after successful and interrupted/corrupt audits; external scratch cleanup only deletes the current operation work.
8. External integration test implements CeAuditVisitor using only crate-root public names (TreeNamespace, TreeKey, LeafValue, CeAuditError) and composes CeBodyAudit; catches private-type leakage that owner-internal tests miss.
9. GcPending after one deletion page and after final deletion before Released is valid structurally; Released has no complete-body requirement. A shared live lease still requires its complete union. A wrong authenticated JobIntent partition root/count fails even when all individual body hashes are well formed.
10. Native Q=0 empty CE audit follows the explicit genesis branch. Different Q/P heights or hashes preserve independent structure results and return Incomplete for equality; provenance metadata is not mislabeled as authenticated body content.

## Definition of done

1. All native CE records and live primary/index populations are covered, with independent root/branch reconstruction and bidirectional membership checks; point reads alone cannot yield complete success. Full live equality additionally requires matching Q/P height and hash; stopped-writer status alone never satisfies that requirement.
2. Bounded visitor/body APIs are callable from the binary without private table access, writable handles or whole-dataset allocations. Matching-frontier requirement and retained-body separation are visible in results.
3. All owner and binary integration tests, fmt and affected zero-warning Clippy pass with assigned CPU limits; no consensus/storage format or runtime writer behavior changes.
4. One semantic pass each for readonly.rs, proof.rs, CE api.rs, Tribute repository/retention and Nod repository. All audit algorithms and owner APIs for downstream task06 are finalized here; later callers/registering modules do not reopen those owners.
5. No removed verifier or placeholder is referenced. New-file declarations, exports and test registrations above are included in the same compiled validation change.
