# 04. Verify retained headers and the current EVM state

Beads: `outbe-chain-g14b.21`. Baseline: `e5d545cedc872c0e579fd3535e7638d883d5b1f5`.

## Outcome

Optional offline validation of retained header continuity and the complete current EVM state/code for native Reth v1/v2. Recompute a root in disposable validation scratch only to compare commitments; never replace/rebuild installed native state or require this calculation before ordinary startup.

## Dependencies and delivery

Depends on: 01.

Part of the optional offline-validation PR with tasks05+06; independently testable native verifier/adapters, never a runtime startup requirement.

## Implementation

1. Current source and input-sufficiency evidence: design/fullnode-state-sync/validation-audit.md and data-layout.md; current task clauses incorporate the audit corrections. Existing API names are evidence; proposed new owner APIs are concrete implementation requirements, not already implemented features.
2. Use task01 parsed native paths and RO handles. Read ChainState at the exact LastFinalizedBlock key for H; retain Execution E, Finish, CE Q, projection P and closure C separately. Metadata(storage_settings) absent selects supported legacy v1; malformed present JSON is corruption. Recognize incomplete/unwind state explicitly and do not recover it offline. Specifically inspect partial_state_trie and unwind progress: pinned Reth can persist Finish with account/storage updates masked by a later suffix. Require a complete current-state image for root success. A mixed/partial image is Incomplete under this algorithm; neither raw Finish nor the smaller partial frontier alone is a valid substitute. Normal graceful head persistence uses equal complete frontiers; do not modify shutdown or invoke source recovery.
3. Header traversal is over actual retained canonical intervals, not a mandatory genesis-to-E chain. Discover segment bounds from native static-file metadata; stream every retained header, require number correctness, recompute native OutbeHeader hash, compare canonical hash/index records and join consecutive parent hashes across contiguous segment boundaries. Record retention boundaries/gaps. A missing interior record in an advertised interval is corruption; an unavailable requested header outside retention is incomplete. Check configured genesis/network against available native identity records separately; do not invent a genesis traversal requirement or an independent consensus-finality proof.
4. Implement read_header_ce_commitment with existing outbe_primitives::reshare_artifact::decode_outbe_block_artifacts(&header.extra_data), take compressed_entities_root and require supported scheme plus exact marker Q/hash/root when applicable. The decoder already validates magic/version/tag/length/duplicates/trailing bytes. Empty extra_data is not a present CE commitment. Genesis uses the native sealed_root(ZERO) initialization rule as a separate case.
5. Create a fresh writable scratch MDBX outside every source/protected/output root. Source opens only with open_db_read_only and StaticFileProviderBuilder::read_only. Read v1 PlainAccountState completely, keccak addresses into scratch HashedAccounts; read every PlainStorageState duplicate, keccak address and slot into scratch HashedStorages. For v2 copy authoritative HashedAccounts/HashedStorages unchanged, never double-hash and never require populated plain tables. Decode native rows, reject malformed/duplicate/orphan storage representation rather than silently discarding it.
6. Keep scratch AccountsTrie/StoragesTrie empty. Use reth_trie_db::DatabaseStateRoot::from_tx on StateRoot<DatabaseTrieCursorFactory<_,LegacyKeyAdapter>,DatabaseHashedCursorFactory<_>>, then root(), to compute from scratch hashed state. This independent legacy scratch encoding works for both source layouts; do not copy or trust source trie caches or use source incremental_root. Compare against canonical header(E).state_root. Demonstrate the exact pinned API by compiling real v1/v2 fixture consumers as part of implementation.
7. Check every referenced nonempty account bytecode hash: require the Bytecodes record and hash its original bytecode bytes with keccak256. Audit declared Bytecodes key/content consistency too. Missing or altered code fails even when the account/state root matches. A poisoned derived v1 hashed cache cannot replace authoritative plain rows during calculation.
8. Default and full EVM validation end at complete actual E; a legitimate complete E>H tail is preserved. Base OCOMP comparisons read immutable canonical JobIntent/finality fields from verified current E and bind referenced B to its retained canonical header. They do not require historical state B or changesets (B,E]. Remove prepare_selected_historical_state, descending rewind scheduling, historical scratch handle lifetimes and related tests from this feature. Pruned historical changesets do not prevent current E validation; required missing headers/frames remain named missing inputs.
9. ScratchStorageReader::read_storage(Address,B256) computes keccak address and slot, cursor_dup_read::<HashedStorages>(), seek_by_key_subkey, and accepts only an entry with exactly matching slot hash; otherwise ZERO for a genuinely absent slot. Implement read_canonical_block_hash from verified retained headers. Instantiate ReadOnlyStorageProvider::new_with_block_context with verified E chain_id/genesis_hash/number/timestamp, then StorageHandle::new. Import StorageReader/ReadOnlyStorageProvider/ReadOnlyBlockContext from storage::readonly, not the storage root. Do not implement a fake StateProviderFactory or open source execution RocksDB.
10. Canonical job adapters call existing outbe_metadosis::api::{get_offchain_job,get_active_lysis_generation,get_lysis_terminal_receipt} with StorageHandle, decode returned native OCB1 types, and enforce expected intent/job/day bindings. Intex authority uses existing outbe_intex::api::certified_contributor_generation(&handle, WorldwideDay). NOD authority uses existing public NodContract::ocomp_certified_generation(day) and ocomp_materialization_head(). Keep raw Metadosis schema private. The new owner live-job view below is the only new core Rust API; other typed getters already exist. No new ABI selector or storage schema is introduced. Each getter reads the same verified E view; historical block hash/state-root values come from retained headers and immutable job fields, never an E view mislabeled as historical B.
11. Never call pinned RocksDBBuilder::with_read_only on source: it creates a sibling rocksdb-secondary-tmp directory. The selected header/state/getter route needs MDBX and static files only. Copy/archive integrity is not a claim of semantic verification of every execution-history RocksDB index. Resource work stays in external scratch, cleaned only when owned by this operation; no source truncation, stage rewrite or shared runtime gate.
12. NativeReadSelection controls inspection prerequisites. Preserve strict create inspect_stopped_stores from01, but expose per-domain observational readers in this planned native.rs pass. A selected evm/header check must not open or require unselected OCOMP closure/pin/CE/projection stores. Validation planner expands only actual prerequisites, not the entire creation inventory.
13. Keep one immutable root-verified E scratch view for the audit lifetime. Complete current-state checks precede dependent OCOMP checks; no relation rewinds or mutates that view. Collect required historical header/frame identities separately and report their actual coverage. Dropping old changesets is not an error for these base checks.
14. Apply NativeReadSelection before required configuration resolution as well as before opens: resolve_requested_layout needs only execution/header inputs for evm-only. Missing projection TOML, CE or OCOMP must not become an unrelated precondition; complete-create path remains strict.
15. Add outbe_metadosis::api::read_live_ocomp_jobs(storage:StorageHandle)->Result<Vec<(B256,OcompJobRecordV1)>>. Inside the owner use poc_schema_limits, perform the exact bounded preflight below BEFORE aggregate loading, then ValidatedWwdAggregate::load_and_validate and existing MetadosisContract::live_ocomp_fsm_states; require each live_intent_id and canonical ocomp_job_record, status AwaitingFinality/VotingOpen, unique intent/day and exact active OffchainPending membership. Preserve deterministic native scheduler order and MAX_ACTIVE_WWDS bound. Return typed observations, no FSM/mutation handle; add only an api.rs Rust re-export because the ocomp module is private; no precompile export is required. Snapshot adapter cannot directly call today-private live_ocomp_fsm_states.
16. Extend the existing current-E canonical adapter with nod_materialization_bounds()->Result<(u64,u64)> and nod_materialization_day(sequence)->Result<WorldwideDay> from existing public NodContract typed head_sequence/tail_sequence/queue_wwd fields. Expose certified_generation and head getter separately; head alone is not full-queue discovery. Add existing Intex total_series, series_id_at, read_series, certified_contributor_generation, certified_payout_round and paid_leaves_word adapters. Compare raw typed series_id_at_index word to decoded id.to_word to catch padding discarded by the public getter. Use only the verified E StorageHandle and existing owner native types.
17. Canonical-state adapter method contract (reuse an equivalent existing planned getter, no synonym API):
    
    ```rust
    live_ocomp_jobs() -> Result<Vec<(B256, OcompJobRecordV1)>>;
    nod_materialization_bounds() -> Result<(u64, u64)>;
    nod_materialization_day(sequence: u64) -> Result<WorldwideDay>;
    nod_materialization_head() -> Result<Option<NodMaterializationHeadV1>>;
    nod_certified_generation(day: WorldwideDay) -> Result<Option<NodCertifiedGenerationProjection>>;

    intex_read_series(id: SeriesId) -> Result<SeriesRecord>;
    intex_certified_contributor_generation(day: WorldwideDay)
        -> Result<Option<CertifiedContributorGenerationProjection>>;
    ```

    OcompJobRecordV1 and ActiveGenerationV1 are public outbe_ocomp_protocol::state types. These Rust observation methods are not a serialized snapshot schema or runtime ABI. Native owner getter validation remains authoritative; all methods read the same verified E view.
18. Exact owner-only preflight for read_live_ocomp_jobs, before aggregate/native variable payload reads: (1) MetadosisContract.active_wwd.len() <= MAX_ACTIVE_WWDS and closed_wwd.len() <= MAX_RECORDS_KEPT before read_all; these use native Set u32/Deque u64 lengths, not active_wwd_count. (2) StorageBytes::len() bounds scheduler by LIVE_INDEX_HEADER_LEN + SCHEDULER_ENCODED_LEN*u16::MAX, ready index by READY_INDEX_HEADER_LEN + READY_INDEX_KEY_LEN*MAX_RECORDS_KEPT, response index by RESPONSE_INDEX_HEADER_LEN + RESPONSE_INDEX_KEY_LEN*u16::MAX; checked arithmetic, reuse constants via pub(super). Empty bytes are interpreted by native decoders. Response windows can outlive live jobs, so never cap response count at MAX_ACTIVE_WWDS. (3) Read the now-bounded active/closed sets; bound each indexed WWD FSM bytes to zero or exactly SCHEDULER_ENCODED_LEN. Bounded-decode scheduler and reject every referenced WWD outside the bounded active set BEFORE native live_ocomp_fsm_states/aggregate follows it; otherwise an unindexed foreign FSM payload could bypass preflight. (4) Run unchanged aggregate/scheduler/native canonical getters for all semantic equivalences; require exact expected active OffchainPending set and bounded return Vec. Existing read_canonical_optional caps canonical job/receipt bytes and existing registry/test-profile readers cap profile bytes; reuse them without duplicate guessed limits. All new preflight logic stays in views.rs; no ordinary reader or writer is hardened/replaced by this task.
19. Every scratch trie/root operation in this task belongs exclusively to the operator-selected validation command. It produces a comparison result and disposable scratch, never deployed state. Transfer/file placement and ordinary startup do not invoke these algorithms. Snapshot size or chain height never introduces a mandatory pre-start state rebuild.

## Tests first

1. RED first: genuine nonzero v1 and v2 native fixture roots reproduce canonical E, including v2 with empty plain tables. Corrupt a plain account/slot in v1 and hashed account/slot in v2; each fails. Poison v1 derived hashed cache and source trie while authoritative state is correct; calculation must use canonical state, with explicit limits on any separate cache-integrity claim.
2. Bytecode missing/modified under unchanged code hash fails although account root bytes are untouched. Orphan storage, malformed native row, and malformed-present storage_settings fail; absent settings alone selects v1.
3. Retained headers starting after genesis pass their available-interval audit with correct configured identity; wrong parent/hash, missing middle header and corrupt range metadata fail. Missing history outside retention is reported only as incomplete for selected checks that require it. Valid E=H+1 passes default current-state validation without H changesets.
4. Current E and immutable current-job bindings pass with historical changesets pruned; a retained B header verifies recorded request hash/state root without opening B state. Missing required B header is Incomplete for that relation. No historical reconstruction helper or hidden changeset dependency remains.
5. Scratch slot lookup cannot return the adjacent greater duplicate. Typed canonical job getter rejects stored IntentId mismatch and malformed OCB1; Intex residual absent state and NOD malformed head fail owner validation. Context and canonical hash reads correspond to the same verified E; historical header identity reads remain distinct.
6. Header CE tests cover missing/duplicate tag, wrong scheme, correct root under wrong block hash, trailing bytes and legitimate genesis handling.
7. Success and every failure leave authoritative source bytes, directory membership, configuration and keys unchanged; account for documented MDBX reader bookkeeping separately. Assert no source-side secondary RocksDB directory and no ordinary node startup.
8. Use native masked-row partial-persistence fixture: Finish/header2 with partial frontier1 and excluded account/slot updates cannot report a complete root at either inferred height. Complete graceful-head fixture at E passes; explicit unwind/partial state returns Incomplete without source mutation.
9. Selected evm/header readers succeed on a valid native execution fixture with absent/corrupt unselected OCOMP closure/pin and projection domains; strict creation inspection still requires its declared complete inventory.
10. evm-only CLI with no projection storage-config and absent CE/OCOMP roots passes its execution checks; all/ocomp selection reports missing required configuration specifically.
11. Owner live-job view: empty/AwaitingFinality/VotingOpen cases, deterministic no-write output, malformed scheduler header, active OffchainPending omitted from index, scheduler outside active set, wrong/missing job, terminal record illegally live and native capacity violation. Tests use native aggregate fixtures, not a mocked list.
12. Canonical adapter fixtures expose multiple NOD sequences and all Intex series/round/bitmap words at the same E; preserve readonly source and exact field encoding, including raw series-index padding checks.
13. External outbe-chain fixture imports outbe_metadosis::api::read_live_ocomp_jobs and names its returned protocol types; owner-only tests cannot conceal private module/type leakage.
14. Tracking StorageReader fixture permits scalar length reads but fails on forbidden payload slots: oversized active/closed counts, scheduler/ready/response bytes or indexed FSM bytes reject before allocation/traversal. Bounded scheduler referencing a foreign day rejects before reading its FSM. Within-bound malformed codecs still fail natively. A legitimate Completed response window remains allowed; response cap is not active-only.

## Definition of done

1. Actual E root independently verified for both pinned native storage layouts with no unverified source trie shortcut, runtime provider construction or upstream patch.
2. Retained header intervals, required unavailable identities, bytecode coverage and current-state completeness are explicit. Header continuity is not full block-body/receipt validation, EVM replay or independent finality proof; no genesis traversal, H rewind or historical EVM proof subsystem.
3. Scratch typed getters compile and execute against native fixtures; no remaining generic getter/reuse placeholder and no public Metadosis schema exposure.
4. Focused native tests, fmt and affected zero-warning Clippy pass with the assigned CPU cap. No external dependency identities change.
5. Semantic pass budget: native.rs task01 then04 only; new validation modules are implemented once here and later registrations are administrative. Root composes these with tasks05/06 into a usable validation PR.
6. One read-only Metadosis Rust view is implemented in its owner with aggregate-equivalence tests; current-E adapters expose full NOD/series index capabilities before task06 composition. Contract transitions/storage/wire and ordinary scheduling are unchanged by this task.
