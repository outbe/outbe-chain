# 06. Validate read-only OCOMP relations and expose the standalone audit command

Beads: `outbe-chain-g14b.23`. Baseline: `e5d545cedc872c0e579fd3535e7638d883d5b1f5`.

## Outcome

A standalone offline snapshot validate command reports archive/provenance checks when supplied and verifies selected native chain/EVM/CE/body/OCOMP relations at their actual frontiers. It reads public OCOMP artifacts through nonmutating owner APIs and never imports donor signing authority or controls node startup.

## Dependencies and delivery

Depends on: 02, 03, 04, 05.

Optional standalone validation delivery with tasks04+05+06. Ready-file placement and ordinary startup are usable without running it.

## Implementation

1. Current source and input-sufficiency evidence: design/fullnode-state-sync/validation-audit.md and data-layout.md; current task clauses incorporate the audit corrections. Existing API names are evidence; proposed new owner APIs are concrete implementation requirements, not already implemented features.
2. Keep cheap task01 independent: reuse per-domain native observations from04, existing inspect_retention_journal and task01 inspect_closure_checkpoint. The spool owner receives at most two semantic passes: checkpoint inspection01 and complete reader06. Every other listed existing OCOMP owner receives one semantic pass here; exports/module registrations are administrative. No changes to source runtime constructors, contract semantics or protected submission journals.
3. Use existing FilesystemCasReader::open/read_verified and ExportReceiptReader::try_open/open/load_exact. Existing list_prepared_export_jobs creates its base directory, so the new read-only listing must share parsing without that create. Use VerifiedInputChunkRefCatalog::reopen/exact_verified_cursor with a nonblocking shared read-only lock open: acquire_shared uses O_NOFOLLOW|O_NONBLOCK, rejects nonregular opened descriptors, then applies LOCK_SH|LOCK_NB. O_NOFOLLOW and nonblocking flock alone do not prevent a FIFO open from hanging. Require its native lock placeholder in complete catalog inventory; missing lock remains an error, never create it offline.
4. ExportedManifestBindingReader shares canonical locator/CAS/input manifest/bundle/catalog and finality comparisons with current load_exact. Its audit authority is the verified current-E JobIntent and immutable finality binding plus surviving native generation/receipt records; do not require a DiscoveryRecord already retired by native closure. Existing spool records, when present, must agree. open_existing performs no mkdir/BindingLock creation. AdmissionCatalogReader holds a private VerifiedAdmissionCatalog immutable view with existing read-only shared lock; LocalLysisPlanAuditV1::open_read_only bridges it to the actual concrete audit. No DerefMut/admit/public inner or runtime behavior change.
5. DiscoverySpoolReaderV1 enumerates existing offers/acks/pending/quarantine/retirements with bounded callbacks and native filename/record codecs, preserving statuses and source identities. Missing/ambiguous temp is an observation failure, not recovery. LocalLysisResultReader opens existing directory, decodes canonical LysisResultV1, checks job/digest and reports pending/conflict state; never calls LocalLysisResultStore::open or reconcile_startup. Native closure deletes offers, ACKs, pending and retirement tombstone; Released pins may also be pruned. Absence of those historical records is not missing current evidence by itself. Partial admissions and missing local result can describe unfinished local work even when the canonical job is Completed; canonical completion is not proof the donor performed local computation.
6. Materialization references live at O/supervisor-v1/materialization-references/<64-lowercase-hex-job>/<first_nod_ordinal>/<job>.materialization-refs-v1.json. Compose caller root and owner filename. Reader performs bounded job/ordinal/file traversal via visit_references(job,ordinal,refs), validates existing directory/regular-file identities without chmod, native ordinal path encoding, exact filename and inner version/job, size/ref limits and native dependency normalization. Retain ordinal as locator, not current canonical cursor authority. Expose no pin_exact/release; missing historical released reference files are allowed.
7. Payout public file is O/supervisor-v1/jobs/<canonical-job>/contributor-payout-v1.bin, owned by payout_artifact.rs. Derive job via task04 get_active_lysis_generation at selected verified state; read Intex certified_contributor_generation for day. File is concatenated84-byte owner20/tribute-ID32/nominal32 records, no new envelope. verify_contributor_payout_artifact requires regular O_NOFOLLOW file, length=count*84, exact EOF/stable identity, decode_contributor_leaf, checked U256 total and native contributor_list_root/StreamingOrderedListRoot with ContributorActions. Compare root/count/total with certified projection; report precise errors instead of submitter runtime skip. Stream rather than load the full file. Do not call writer or payout submitter.
8. Validate C baseline/previous/current against canonical retained headers and native advancement rules, retaining legitimate C<H. Projection coverage must satisfy the closure operation actually recorded. Do not impose C=H=E=Q=P. Required unavailable retained headers, replay frames or current body inputs makes that selected relation Incomplete; no cursor or journal repair. Sparse native closure advancement means previous is not necessarily C-1. Validate its real predecessor/baseline contract, not invented contiguous processing witnesses. For continuation coverage also require the retained canonical block/receipt frames that ordinary C+1 replay and selected local result comparison actually read; root validity alone does not establish frame availability.
9. Inspect every present native PinRecordV1 against canonical immutable JobIntent/finality at verified current E and its retained request header B. Compare intent, WWD, bundle, lease, request block/hash/state-root and job identities. AwaitingJobFinalization/Finalized/Exported/Terminal have their native stage-specific obligations; GcPending permits partial or empty residuals; Released needs no bodies and can be absent after pruning. Match surviving ExportAuthority source_generation/lease_generation/manifest_hash with required receipt/binding records. Evaluate shared live leases before releasing coverage. Current obligations discovered independently of present files/pins must also be checked.
10. For a stage requiring a complete export, verify receipt/prepared/binding, expected CAS kinds and manifest.validate_against_bundle; exact input cursor covers declared ordinals/counts with no missing middle chunk/cross-job substitution. Bind current-E job/finality and surviving native authority, not directory labels or necessarily retained spool records. Validate present plan/admissions and only demand Complete result catalogs where the current obligation requires completed outputs. A present local result must decode and match its job/native stage; compare its digest with canonical terminal binding only once that binding exists, and report the comparison unavailable before canonical completion; no assertion of computation reexecution. Partial native stages remain distinct from corrupt bytes.
11. Use task05 retained scans for present body/index consistency. Complete currently required lease partitions use canonical current-E JobIntent sealed_tribute_collection_root/authenticated_day_count/WWD plus immutable lease/finality binding and the live-or-retained union. GcPending/Released do not demand deleted historical bodies. Payout verification directly uses the current certified root/count/nominal and active job; do not require old CE bodies, admissions or a result catalog after those intermediates legitimately disappeared.
12. Materialization references are retained dependency declarations, not batch/cursor authority. Verify each CAS ref and match the full ref to that job’s plan-bound producer/reducer artifacts or verified result chunks using the existing Lysis audit/catalog; build a bounded scratch membership set for large jobs. Compare native NodContract certified generation job/bundle/program/output roots. References may remain after cursor advancement, so do not require equality with the current batch. If current-batch verification is selected, use existing pure build_nod_materialization_batch_with_references(audit,head,subtree_height) for the matching canonical FIFO head; it performs no pinning/submission. A surviving complete result catalog can additionally be cross-checked against payout leaves, but is not a prerequisite of certified payout-file validation.
13. Payout-submissions, materialization-submissions/submission-v1.json, vote-submissions and sign-once are protected local signing/submission history, not public portability records. Do not open submitters, call reconcile_finalized_materialization_references, release/persist/admit jobs, broadcast, or regenerate a signed identity. The ordinary payout submitter and scheduler remain unchanged; this task only validates public artifacts offline.
14. CLI form: snapshot validate [--checks all|comma-separated-names] [--manifest FILE] [--signature FILE] [--archive FILE] [--expected-signer HEX] [--report FILE] -- <ordinary node arguments>. Native-only validation works without any archive. Fixed check names are files, provenance, headers, evm, ce, bodies and ocomp; selecting a check expands required verification dependencies, never blindly trusts caller-supplied roots. When an archive/manifest is supplied, its mandatory signature uses tasks01/02 exact parsers/digests/signature primitives. Native-only validation remains callable without snapshot metadata. all expands to all native checks and adds files/provenance when artifact metadata is supplied; without metadata those artifact checks are NotRequested, not Passed. Explicit files/provenance or expected-signer expands the artifact prerequisites and reports Incomplete if absent. Expected signer requires verifiable signature data; missing required signature is not unsigned success.
15. ValidationReport records observed H/E/Q/P/C, verified retained intervals, current canonical obligation scan bounds, required retained headers/frames, each check Passed/Failed/Incomplete/NotRequested, and cryptographic signature validity separately from configured signer trust. Default checks=all; requested prerequisites failing/missing make their dependent check non-success. Any selected Failed/Incomplete returns a nonzero CLI status and writes precise diagnostics if report requested. NotRequested is never counted as a passed semantic check. Archive digest/signature success cannot override native corruption. Report is an optional file outside native authority paths and is never read by normal startup. Resolve report output protection independently of check selection, including every explicitly configured native/authority root and projection TOML. If supplied node configuration cannot resolve those roots, print semantic results to stdout but refuse file publication. Artifact-only stdout checks remain independent of native arguments; an artifact-only report with no native arguments needs no native configuration.
16. Orchestrator operates entirely offline on the operator-stopped dataset, uses external scratch and existing immutable source readers, detects observed source mutation and never claims a collective shutdown lock. It starts no runtime, performs no historical body invention and requires no validation receipt for file placement or ordinary node startup.
17. Resolve check selection and its actual prerequisites before opening stores. evm-only requires execution/header inputs, not OCOMP/CE/projection. ocomp uses the root-verified current E view plus specifically needed header/frame identities, canonical obligation enumeration and public artifact readers; no historical-state planner or changeset dependency. all requires its full applicable domain set; missing selected inputs remain Incomplete. Strict complete-create inspection is not the validator entry point.
18. File/provenance validation uses the exact original manifest and signature. Check donor-declared members and exact payload-domain inventory. Own identity/configuration are outside those domains. Extra or conflicting local native members are reported explicitly; the validator performs no merge, relocation, deletion or repair. The old file inventory describes its original cut, not current-K databases after normal work.
19. Before walking local pin/job/catalog/ref directories, acquire one immutable, task04-root-verified state(E) and enumerate three canonical inventories: active nonterminal Metadosis intents; every occupied NOD FIFO sequence; every currently open unpaid certified payout day reachable through the native permanent Intex series index. All subsequent canonical reads use that same E view. Local paths never seed these inventories. Report inventory bounds and visited counts; if a configured resource budget stops a traversal before its canonical end, return Incomplete, never a truncated successful inventory.
20. The existing `NodContract::ocomp_materialization_head()` validates only the head. In task04's existing canonical view adapter explicitly add read-only projections `nod_materialization_bounds() -> Result<(u64,u64)>` and `nod_materialization_day(sequence:u64) -> Result<WorldwideDay>`, backed by existing **public typed fields** `ocomp_materialization_head_sequence.read()`, `ocomp_materialization_tail_sequence.read()`, and `ocomp_materialization_queue_wwd.read(&sequence)`. Use existing `NodContract::ocomp_certified_generation(day)` for each entry. These are new adapter methods over existing owner storage capabilities; no Nod consensus schema or public contract change is needed.
    
    Read head/tail once, require `1 <= head <= tail`, and visit exactly `[head,tail)` with checked arithmetic. `tail-head` is the finite entry count; process entries incrementally, not a tail-sized allocation. Require the next-free tail entry to be zero, consistent with the installation invariant. Empty means head==tail and must agree with the existing head getter.
    
    For every occupied sequence require a nonzero valid day, a present native certified projection, a unique pending day/job, nonzero job/bundle/semantics authority, and `next_nod_ordinal < nod_count`. Native `ocomp_certified_generation` already validates count/generation/root/scalar consistency. Cross-check the first projection against `ocomp_materialization_head()`. Derive the required public job path from the canonical projection's JobId, regardless of whether any directory/ref exists. Reopen its input catalog, pinned bundle, admissions and plan audit; all missing required paths are explicit missing-input diagnostics. Existing JSON reference pins are not a prerequisite for discovering this obligation.
    
    To verify all remaining materialization inputs rather than just the first batch, create an in-memory `NodMaterializationHeadV1` projection for that sequence from its certified fields. Repeatedly call the existing **pure** `build_nod_materialization_batch_with_references(&audit,&projection,subtree_height)` for the selected native/configured subtree height, advance only the local copy's `next_nod_ordinal` by the nonzero returned action count, and stop at nod_count. Require checked strict progress and no overshoot. The maximum batch count is `nod_count-start_ordinal`; memory remains one bounded batch. The builder invokes native `verify_nod_materialization_batch` against nod_root, so this proves public data sufficiency for the remaining batches. For a later FIFO entry, this is future batch evidence, not a claim that it is currently submittable. Never mutate canonical FIFO, pin/release refs, open submission journals, sign or send transactions. Independent canonical queue enumeration detects a missing entire later job even when the head job is complete locally.
21. For every active canonical intent returned by task04, derive local obligations from each record and the native P/C/pin/export stage. Awaiting-finality or not-yet-exported work does not require a fabricated completed admission/result directory. If work has not yet been exported, check that the required current/retained source union and native request/header/frame inputs allow the ordinary export path, or report missing inputs for that capability. If export is recorded as complete, require its exact public receipt/input/binding closure. If a job is locally computing, validate partial admissions according to their stage, without demanding a terminal result. Record every canonical intent in the report even when there is no local pin or job directory; absence must be evaluated explicitly rather than silently skipped. A lagging P before the request is not by itself a missing-pin corruption claim.
22. Freeze N=`total_series`; stream exactly indices `[0,N)`. N is the finite bound, with no 31-day, 365-day, genesis timestamp or current-date cutoff. Validate each decoded SeriesId before `worldwide_day()` because `from_word` and `worldwide_day` are permissive: first eight bytes ASCII digits, positions8/12 separators, three issuance bytes and reference code canonical, day valid/nonzero; reconstruct via `SeriesId::pack(day,issuance,reference)` and compare all14 bytes. Require `read_series` exists, returns the same identity and a matching worldwide_day. Reject duplicate full SeriesIds and holes. Deduplicate days, since several currency series may share a day. This can use external scratch sets bounded by N; do not allocate from an untrusted N up front. Task04 can additionally compare the raw typed `series_id_at_index` word to `id.to_word()` to reject nonzero unused padding; the public getter itself discards that padding.
    
    For each enumerated day read certified generation and payout round independently. No round means **no presently open payout obligation**; a nonzero certified generation may become payable after future proceeds and is not a reason to require a local payout file now. A round without certified authority is inconsistent. For a present round require matching day, native existence sentinel, `paid_so_far <= amount`, `paid_leaf_count <= contributor_count`, and valid certified root/count/eligible nominal (native getter validation). Zero-count/zero-total certification without a round is a valid ownerless case; an opened round with zero certified count contradicts the production opening branch.
    
    For Ncontributors>0 read **all** `ceil(u64(Ncontributors)/256)` words, not one word or the word containing the stored paid count. In the final word mask only actual leaf positions; reject nonzero bits above the count. Sum masked popcounts with checked arithmetic and require exact equality with paid_leaf_count. Fully paid means popcount==Ncontributors; the round is retained after completion, so `active!=0` alone is not unpaid. If any valid leaf bit is zero, this day is a required current payout obligation. Derive the JobId from current canonical active Lysis generation; require the corresponding entire payout file even if there are no local job directories. Verify the full native84-byte leaf list against certified count/root/checked total as task06 specifies. Missing file is Incomplete/missing-input; mismatching file is Failed. Do not import signed journals or treat other nodes' payments as donor corruption.
    
    Why series enumeration is complete for ordinary production open rounds: `intex/api.rs:568–575` exposes the permanent ever-created series index; `intex/state.rs:34–60` appends every new series. `intexfactory/runtime.rs:77` creates/indexes series **before** arming proceeds at123. `try_settle_proceeds` requires an armed deadline at367–377, then opens a nonempty certified round at402–406; finalization removes awaiting-proceeds membership at416–418, so awaiting_proceeds/active_dist alone are NOT complete open-round inventories. `intex/schema.rs:315–322` explicitly retains completed round accounting; `intex/api.rs:517–547` records paid bits/counters. Certified generation without an existing series is supported (`intex/schema.rs:565–570`) but alone cannot create a presently payable round through this normal path.
    
    Scope limitation must be explicit: this completeness statement concerns ordinary production transitions and their native indexes. `intexfactory/precompile.rs:191–199`, gated by e2e-test, can arm arbitrary days without creating a series. Arbitrary manually seeded genesis/storage can similarly bypass indexes. Such injected out-of-index state is not covered by this production completeness proof. A known injected fixture must be identified as unsupported for this inventory claim or provide an explicitly reviewed complete candidate set; never silently call its unindexed round absent. Do not pretend the current per-day API detects arbitrary unreachable hidden map keys. No all-u32 scan, calendar workaround, or new consensus index is proposed.
23. Offline inspection of retained payout rounds/artifacts is observational only. It must not extend the runtime candidate-date window, introduce historical scheduling, submit transactions, or make snapshot creation/startup depend on discovering or paying historical obligations.

## Definition of done

1. Standalone validate command is usable with ordinary native arguments on placed native files or existing stopped data, with optional artifact/provenance input. Every selected check and prerequisite has truthful Passed/Failed/Incomplete status and useful nonzero failure output.
