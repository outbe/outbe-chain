### Payload и immutable approval

Canonical V1 JSON строго фиксирует version1, nonzero repo/patch/revision/expectedTargetHead, `action=accept`, `targetBranch=main`. Decode ограничен512 bytes **до** JSON parse, deny_unknown_fields/serde rejects duplicates, затем exact encode equality исключает whitespace/order/escape/uppercase alternate encodings. Предмет не заменён code merge commit и не используется latest revision. Git existence/signatures намеренно проверяются будущим signer после finality, а не Vote callback.

Validate проверяет формат; reserve проверяет registered repository. Reserve выполняется после proposal allocation/electorate write внутри `commit_proposal` checkpoint. Unknown repo не оставляет counter/policy/pending state; test сравнивает весь storage до/после. Нет attached-value fee или signer/sidecar доступности, необходимой для patch target.

`handle_approved` принимает Pending потому, что production Vote вызывает его **до** terminal status write; это корректный внутренний порядок callback. Внешнего ABI «создать approval» нет. Он проверяет exact stored target/payload/proposer и closed deadline. Запись approval и Pending stage затем коммитятся только вместе с terminal Approved и событиями. Reader независимо требует terminal Approved, поэтому одна row не даёт permission. Повтор того же payload сохраняет первоначальные approved_height/timestamp и stage; revision substitution отсекается сравнением со stored proposal.

### Electorate и неизменность принятой истории

Тесты используют real validator lifecycle transitions и production Vote runtime, не подмену tally. Source validatorset `state_machine/adapter.rs:409–427` определяет Active отдельно от Exiting/JailRetained effective membership. Canonical Active всегда имеет live share (`state_machine/state.rs:39`); patch policy всё равно явно вычисляет пересечение через effective query и status, не смешивает будущий Joining с current set. Pending joiner не голосует до activation; после неё текущие denominator и разрешённые ballots меняются. Jailed retained member остаётся effective для consensus, но не влияет на patch cast/tally; ранее поданный его Yes исключается при tally.

Admission policy type хранится per proposal, а membership читается current при cast и tally. Default ACTIVE сохранён для других targets и absent legacy slots. Numerator/denominator теперь строятся одним helper; для default list/count соответствуют прежнему canonical ACTIVE query. Quorum остаётся `yes*3>=count*2`, empty electorate не одобряет. Membership changes после terminal Approved не вызывают retally/status transition и не отзывают immutable approval. `get_proposal` может отображать current filtered vote counts, но это не permission predicate; `patch_approval` читает terminal status/payload, не пересчитывает Yes. ### Exact finalized reader

Reader сначала получает `finalized_block_num_hash`; проверяет requested height≤finalized, canonical hash requested height совпадает с supplied hash, canonical hash finalized height совпадает с finalized pointer. Лишь после этого читает состояние по exact block hash. No finalized block, wrong canonical pointer/hash, unavailable exact state дают typed error без latest/pending fallback; approval height новее source snapshot запрещена.

Provider fixture хранит разные **immutable states per hash**, а APIs latest/pending/tag/history fallback panic. Воспроизведены: до terminal hash — None, terminal snapshot — exact payload/height/time, более новый ещё не finalized — error, после finality — тот же approval несмотря на jail; поздняя повторная historical read даёт прежний exact record. Это поведенческая проверка production reader с controlled provider, не полноценный multi-validator finality experiment. Trust boundary — собственный validating node canonical/finalized provider, как предусмотрено design.
