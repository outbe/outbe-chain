## Detailed source/caller assessment

**Codec and immutable subject.** `PatchVotePayloadV1` caps decoding at512 bytes, denies unknown/duplicate fields through Serde, validates version1/action accept/branch main/nonzero OIDs, and compares re-encoded bytes to input. Alternate field order, whitespace, escapes, uppercase OIDs, alternate numeric encodings and trailing material cannot select a second byte representation. Record stores the complete canonical subject, including expectedTargetHead; later revision or branch-precondition substitution is not inherited. Git existence and author/content integrity are intentionally not checked in consensus; P6 signer must check them before partial issuance. No user delegation, owner-key mutation or approval-revocation endpoint is introduced.

**Admission and actual terminal wiring.** Vote precompile dispatch calls the EVM-owned static handler registry; `executor/hooks.rs:111` invokes VoteLifecycle with that registry. Radicle's `reserve` checks the existing owning repository registry inside Vote's admission storage checkpoint. Unknown repository failure restores count, proposal data, electorate and related state, demonstrated by exact before/after storage and next ID1. No separate unrelated registry is created. Radicle callback is reachable through the normal generic tally dispatch after deadline, not a test-only approval endpoint. The EVM fixture executes register/create/ballots/getters as actual transactions and runs the actual pre-execution hooks. Fixture setup seeds validator records; this is not a claim of running genesis/DKG or a live network.

**Current electorate and retained behavior.** Cast first checks ACTIVE, then membership in the persisted policy's current eligible list. Tally calculates Yes/No and count from the same current list; quorum rejects n0 and uses wide arithmetic for yes*3≥count*2. Policy is chosen by the trusted target rather than payload/RPC. Current `ValidatorSet::get_active_consensus_set` uses the lifecycle current-participant predicate, which includes accountability-retained Exiting/JailRetained; filtering ACTIVE removes those. Pending joiner becomes eligible only after canonical activation. Existing ACTIVE list and active_validator_count both use the same `is_active_status` predicate over the dense registry, so using list length preserves valid default-target denominator semantics. Absent slot13 defaults0/Active. Invalid stored policy fails closed. Unchanged target suites, Vote lifecycle/bond/error tests and EVM factory/L2 wiring tests run in the full suites.

**Irreversible permission versus execution.** Approval record binds proposal ID through map key and stores exact payload/first terminal height/timestamp. A matching callback replay preserves the first record and does not reset stage. Substituted payload is rejected before mutation. Read API requires actual Approved state and exact matching target/payload; Pending/Expired/Error do not grant permission even with a manually seeded approval row. Normal terminal states are not reexecuted, and no public cancellation/revocation exists. A later membership change changes current tally views, not the accepted permission. Execution stage is separate and starts Pending; this does not assert Review, Merge, signing or publication completion. Concurrent distinct approvals remain distinct proposal permissions, as expected by the later ordered execution contract.

**Failure and atomicity.** Vote finalization encloses target writes, terminal status, pending-index removal, bond changes and events in its existing checkpoint machinery. P5 fault injection visits every terminal mutation through eventual success and compares storage/events against pre-finalization state for failures. The full Vote suite additionally exercises target-declared Error rollback/terminal Error/no replay and infrastructure failure rollback with status remaining Pending. Radicle's post-admission target has no mutable external/Git dependency; malformed or inconsistent stored state fails through the outer Result, preserving existing infrastructure/error semantics. Callback cannot authorize a nonapproved state merely by leaving an uncommitted row.

**Exact finalized read boundary.** RethSnapshotReader checks requested height≤finalized height and both requested/finalized canonical hashes before opening exact hash state. Provider errors propagate. `ReadOnlyStorageProvider` supplies storage-only access with immutable chain identity; this getter requires no zero/default block-time-dependent computation. Approval's height is checked against requested snapshot separately. The fixture's latest/pending/number-tag APIs panic, so a passing test demonstrates the exact path rather than a convenient shared/latest mock. Existing node launch constructs this reader from the node provider, chain ID and genesis hash; the new public approval method is an exposed consumer seam. P6 consumer/signing wiring is not claimed implemented by P5.

**Schema/ABI/bounded work.** Storage-record generated layout and actual tests pin the append-only slots. Existing registry/genesis slot fixtures still pass13 tests. Solidity `PatchApprovalInfo` returns bool/string/uint64/uint64; getter false response is empty/zero; stage getter returns0 if no valid approval, otherwise separate stage. Source import closure for payload/target/runtime contains no Git/client/signer I/O. n256/q171 test measures maximum cast storage gas1,121,500 and terminal1,228,600, within its2M/5M assertions; this is the production storage meter, not a256-validator network benchmark or a full cold-state EVM cost measurement. A separate actual EVM scenario proves dispatch/hook execution at n3. No broader performance/network claim is made.
