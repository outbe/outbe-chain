# Full-chain E2E source readiness

Requested: implement the entire happy-path scenario; leave execution to the user.

Implemented in `testing/e2e-harness/features/radicle.feature` under
`@governments-patch-vote` with existing scenario/process/evidence infrastructure.
Production genesis and DKG create governments; independent author submits a real
Ed25519 patch; four actual current validators transact through Vote; their finalized
approval binds the exact revision; the production workers publish native BLS
Review/Merge. All four replicas verify native objects against their own finalized
receipts. A fresh FullNode becomes an active validator via real registration/DKG,
then verifies the accepted history without re-voting. A fresh ordinary Radicle
reader receives the merged repository through native Fetch without an Outbe policy.

No chain-state, approved-package, signature or share injection is used. Observation
never installs refs, and cannot create a missing runtime managed owner pin.
The test profile uses epoch96/prepare15/grace20, and a24-block voting window.

`checks.json` records successful compile/lint/format/diff checks.
`source-manifest.json` records the exact eight-file source input.
`reviews.json` records three independent source-only PASS reviews on that input,
after resolving startup-window, observer-side-effect and native-Fetch-framing findings.

Run commands and prerequisites are in `plans/radicle-patch-vote/runbook.md`.
Runtime evidence will be generated by the existing scenario evidence writer, with
proposal/ballot IDs, finalized approval, receipt/manifest bytes and native replica
observations. No E2E, tests, SGX artifact build, or required CI was executed here.
P8 and feature acceptance remain open until their required runtime proof exists.
