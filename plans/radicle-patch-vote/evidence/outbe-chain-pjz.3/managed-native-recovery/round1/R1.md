## R1-F1 — Present tip with missing reachable object cannot be fetched again

Acceptance AC4 explicitly requires missing object bytes to remain recoverable. The current pure unit checks a completely empty receiver ODB (`bootstrap/tests.rs`, `empty_storage` case); it does not cover a partial ODB with a retained tip commit and a missing required descendant.

Concrete source trace:

1. A receipt-bound manifest is cached. Its owner sigrefs tip exists in the receiver ODB, but a required tree/blob is absent from both that ODB and the package's object archive.
2. `publication/store.rs:607–637` recognizes the missing bytes and returns `Ok(None)`, which sends the collector into `recover_history` (`collector.rs:630,647+`).
3. The prefetch uses `WantsHaves::add` (`radicle-fetch/src/state.rs`, preparation block). That existing helper requests nothing when the advertised tip is already present (`transport.rs:309,317`); `git/repository.rs:38–42` checks only `odb.exists(tip)`, not closure completeness. The same happens if an installed local ref already equals that tip.
4. With no wants, pack acquisition is skipped. `history.rs:235–239` or subsequent native reconstruction encounters the same missing descendant. Repeating the collector tick cannot change those bytes.

This is an availability gap, not unauthorized acceptance: the path still fails closed. The smallest correction is to make this explicit missing-closure recovery case issue a native Git want that actually retrieves its missing bytes, while preserving ordinary incremental fetch for intact repositories. A focused pure unit for present-tip/missing-descendant request selection is sufficient at this stage; no E2E is requested.
