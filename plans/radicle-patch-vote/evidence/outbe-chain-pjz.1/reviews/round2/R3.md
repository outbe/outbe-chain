## Required clarification

### R3-R2-F1 — medium: genesis descriptor hash has no explicit cycle-free preimage

`design.md:355–358` places the descriptor in genesis and says its hash includes "chain identity", but does not define that hash preimage or exclude `genesis_hash`. The same design represents chain identity using both chain ID and genesis hash in `PublicationBody` (`design.md:207`) and OPJ1 (`design.md:397`). Current genesis seeding config has chain ID before construction (`scripts/genesis_network.py:264–287`); `seed_radicle_registry` currently writes genesis allocation capacity (`scripts/genesis_seed_alloc.py:94–106`). A descriptor/hash seeded into genesis state cannot also depend on the final genesis block hash: descriptor → genesis state root → genesis block hash → descriptor is circular.

This is an ambiguity in the selected design, not a claim that any current production implementation computes such a circular hash. The safe interpretation is implementable: commit canonical pre-genesis descriptor bytes including chain ID and fixed initial content/policy, explicitly exclude genesis hash/RID/not-yet-produced DKG group key, and later bind its hash to the actual genesis hash/RID/material in authenticated OPB1. OPB1 already has independent `genesis_hash`, `descriptor_hash` and owner key fields, so this preserves cross-genesis protection without self-reference. However, this safe interpretation is not explicitly selected in the frozen descriptor definition. Neither native RDB1 vectors nor the reduced publication model covers descriptor construction, so they do not resolve this gap.

Required before P0 closure: specify exact canonical descriptor fields/encoding/hash domain and the known-before-genesis chain identifier; explicitly prohibit final genesis hash, derived RID and future group key in the genesis-seeded hash preimage. State where subsequent OPB1 binds the final genesis identity and authenticated DKG result. Add a small finite descriptor-hash example or dependency trace proving genesis construction does not require its own resulting hash, plus a cross-genesis OPB1 binding negative. No production P4 implementation/test is requested at P0.

This point was raised by the coordinator as an independent source question after I had drafted a provisional PASS, before report attachment or child closure; I inspected the frozen text/source and changed the verdict. No peer report was read.
