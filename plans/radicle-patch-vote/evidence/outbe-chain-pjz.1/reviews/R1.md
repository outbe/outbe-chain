## Must fix

1. **The managed gate has no admission rule for the author's patch before Vote** (`design.md:15–30,162–173,219–230,296–309`).
   - **What this is:** The gate covers local writes, fetch, refs, identity, and cache promotion. Quarantined objects cannot affect the patch evaluator, and every promoted managed package needs a finalized checkpoint.
   - **Problem:** An ordinary Ed25519 author must first create and replicate a patch/revision so validators can inspect it. Its author COB and author sigrefs are not BLS authority writes and have no bootstrap/bind/review/merge checkpoint. The current text therefore either blocks this required pre-Vote step, or leaves an undocumented exemption that an old BLS owner could try to use. Saying that ordinary *repositories* keep native rules does not define ordinary author operations *inside governments*.
   - **Live source:** `vendor/heartwood/crates/radicle/src/cob/store.rs:268–359` writes the signer's namespace and signed refs; `cob/patch.rs:835–870` distinguishes delegate actions from author actions and allows ordinary reviews. `radicle-fetch/src/stage.rs:8–30` fetches delegate and other namespaces. `radicle-fetch/src/state.rs:653–664` promotes the resulting refs. `radicle/src/cob/patch/cache.rs:184–239,456–469` populates and reads the patch cache. These are distinct authority and author paths, not one owner-only object stream.
   - **Fix:** Specify the protected namespace/action boundary and the native author admission rule before P0 closes. Map it through local mutation, fetch, evaluator, cache reopen/rebuild, and direct lookup. Include a design scenario where an unapproved Ed25519 patch/revision reaches another validating node, while forged old-owner delegate operations cannot enter through the same exemption. Production implementation is still P2/P6.
   - **If we skip it:** The required author→Vote flow either cannot start or depends on an unspecified receiver bypass.

2. **Different valid partial subsets can permanently lock the checkpoint** (`design.md:164–180,210–217`; `p0-check/src/publication.rs:70–87`).
   - **What this is:** The manifest hash commits to q partial frames for each native subject. Each participant gets one body slot for a repository/epoch/sequence, and cannot change to another body for that sequence.
   - **Problem:** With n=4/q=3, collectors X and Y can recover the same native signature from valid subsets `{0,1,2}` and `{1,2,3}`. Both packages pass the specified checks but their proof lists and manifest hashes differ. Deliver X first to two honest attesters and Y first to the other two. All four valid attestations are accepted, neither body gets three, and subsequent delivery of either complete package cannot move a participant's slot. The committee is stable, every participant is honest and online, and no transition exists that restores progress. Sorting frames only orders a chosen subset; it does not make different subsets identical.
   - **Reproduced evidence:** A private copy of the original model used real native partials and real current identity signatures, then exercised that 2+2 schedule. It printed `COUNTEREXAMPLE PASS: 4 honest current identities, two valid partial subsets, split 2+2; no receipt and all switches rejected`, exit 0. Original candidate files were unchanged. The reproducible extension is below.
   - **Fix:** Define how independent collectors and attesters converge on one body without requiring all n participants or a designated proposer, while preserving safety and bounded state. Separating interchangeable contribution witnesses from the stable checkpoint commitment is one possible small solution, but the selected protocol must state exactly what is committed and checked. Add this schedule to the P0 model and P3/P6 test map.
   - **If we skip it:** A normal concurrent collection schedule can stall bootstrap or a finalized approved execution forever. Current-quorum safety checks do not provide liveness.

3. **Exact new signing and wire vectors are still missing** (`design.md:62,77–87,300–318`; `p0-check/src/main.rs:32–33`).
   - **What this is:** P0 must pin the bytes every independent signer and verifier reconstructs. The selected envelope wraps the correct native subject and also signs metadata and policy context.
   - **Problem:** `canonical commit metadata without signature header` has no byte-level definition: fields, order, parent order, trailers, whitespace/header normalization, and removal of the custom signature header are not fixed. Repository wire messages only promise a future versioned format; no actual version/tag/key field encoding or negotiation rule is selected. Review/merge COB parents also still depend on an unspecified preparation snapshot. Live `radicle-cob/src/object/collaboration/update.rs:84–105` derives tips from locally loaded graph history, while `backend/git/change.rs:125–135,271–346` commits parent order, local author/time, headers, message, and trailers. Two collectors with different fetched tips can therefore prepare different valid bytes unless the contract overrides this behavior explicitly.
   - **Evidence limit:** The real BLS spike proves arbitrary-byte signing and threshold recovery. It does not build an RDB1 message, parse an envelope, serialize a RepositoryKey wire frame, or supply fixed native operation hex vectors. The README correctly disclaims production parsing, but that disclaimer does not supply the mandatory P0 signing/wire vectors.
   - **Fix:** Define the unsigned COB metadata bytes and deterministic parent/resource/metadata selection, select the actual repository key wire/envelope format, and supply small reproducible fixed vectors for identity/COB/refs with positive reconstruction and one tamper/cross-kind case. This is a serialization/design check, not a request to implement P2 production fetch or run P8 E2E now.
   - **If we skip it:** P2/P6 must still make protocol decisions, and independent signers/verifiers need not agree on a message or object ID.

let proof = |indices: &[usize]| {
    let mut bytes = package.clone();

```rust
pub fn split_check(package_a: &[u8], package_b: &[u8]) {
    assert_ne!(package_a, package_b);
    let keys: Vec<_> = (3..=6).map(bls12381::PrivateKey::from_seed).collect();
    let mut model = Model::new(2, keys.iter().map(Signer::public_key).collect());
    let a = Body { chain: 2026, genesis: [7; 32], repo: [8; 20], epoch: 2,
        sequence: 1, previous: [0; 32], manifest: Sha256::hash(&[package_a]).0 };
    let mut b = a.clone();
    b.manifest = Sha256::hash(&[package_b]).0;
    for (i, key) in keys.iter().enumerate() {
        let body = if i < 2 { &a } else { &b };
        assert!(model.attest(body, i, &key.sign(DOMAIN, &body.encode())));
    }
    assert_eq!(model.sequence, 0);
    assert!(model.accepted.is_empty());
    for (i, key) in keys.iter().enumerate() {
        let other = if i < 2 { &b } else { &a };
        assert!(!model.attest(other, i, &key.sign(DOMAIN, &other.encode())));
    }
    assert_eq!(model.sequence, 0);
    println!("COUNTEREXAMPLE PASS: 4 honest current identities, two valid partial subsets, split 2+2; no receipt and all switches rejected");
}
```
