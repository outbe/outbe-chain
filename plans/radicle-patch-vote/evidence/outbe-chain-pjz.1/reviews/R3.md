## Required fixes

### R3-F1 — high: valid candidates can permanently split one-sequence attestations

`design.md:164–170` includes q indexed partial frames in the manifest. With 3-of-4 threshold, collectors using `{0,1,2}` and `{1,2,3}` recover exactly the same native signature (`p0-check/src/main.rs:49–59` verifies this), but their sorted contribution lists and manifest hashes differ. Sorting does not make different subsets equal. `PublicationBody` also contains a finalized anchor (`design.md:148`); `design.md:196–198` allows selection from local finality without choosing one common deterministic anchor.

`design.md:175–178,212–216` then permits only one body per participant/sequence. A valid first attestation permanently occupies its slot; there is no same-epoch cancellation, round change or retry rule. Consequently two independently valid packages can divide four honest current participants 2/2. Neither reaches q=3, and no participant can switch even after every message is delivered. A stable committee and q online honest participants do not restore progress. This can stall the initial bootstrap and every later execution; consensus may continue, but the requested automatic repository pipeline does not complete.

Independent counterexample uses the candidate's unchanged `Model::attest` with real current MinPk signatures. It submits A from indices 0/1, B from 2/3, then retries both bodies from all keys. First submissions succeed, sequence stays 0, every retry fails. The model is reduced and does not prove production behavior; here it demonstrates the exact slot rule's failure, with full-design sources above establishing that two valid bodies are possible. Artifact: `R3-artifacts/liveness-publication.rs`, added function `split_repro`; run log `R3-artifacts/liveness.log`.

Required: choose a concrete convergence/retry protocol before P0 acceptance. It must handle non-identical contribution proofs and anchors without requiring a designated collector or all n participants. Define canonical subject/package/body selection and/or safe round/cancellation/locking rules, with bounded state and an eventual-progress argument. Add a real-signature model scenario for two honest collectors with different valid subsets/anchors, plus an unavailable participant. Merely sorting frames, increasing queue fairness, retrying the same sequence, or waiting for the next membership change does not solve this trace.

### R3-F2 — high: blanket managed-repository gate has no ordinary author namespace rule

The user flow in `plan.md:11–17` requires an ordinary Ed25519 author to create a patch before Vote. Native `radicle/src/cob/store.rs:329–350` creates the COB in the author's signer namespace and immediately signs that author's refs; `patch.rs:2722–2744` uses this path. Authors can also submit ordinary reviews (`patch.rs:869–870`). These are writes inside governments, but are not BLS-owner writes.

`design.md:15–32` requires a chain-authorized package for a new canonical write in any managed repository and gates local writes, fetched refs and patch/cache evaluation. Only bootstrap, material bind, post-Approved Review and Merge publication actions are defined (`design.md:150–163`); no pre-Vote author-write policy exists. The blanket rule therefore either rejects the normal author patch and its refs (or quarantines it out of normal patch evaluation), or forces implementation to invent an unstated bypass. A legacy Ed25519 repository regression test does not address Ed25519 authors inside the managed BLS repository.

Required: explicitly define which keys/namespaces/refs require network checkpoints, and how ordinary author patch/revision/review COBs and Ed25519 signed refs are admitted, fetched and evaluated before approval. Preserve canonical network branch/identity/BLS-owner protection, prohibit using an ordinary namespace as an authority bypass, and define how approved author objects become reachable from the managed publication. Add an explicit managed-governments Ed25519 create→fetch→evaluate-before-Vote scenario and a namespace-confusion negative scenario to P2/P6/P8. No production implementation is requested for P0; the permission matrix must be decided now.

### R3-F3 — medium: carrier map targets a nonexistent EVM system-tx codec

`task-specs.json:125` lists `crates/blockchain/evm/src/system_tx/` without marking it new. That directory does not exist. `crates/blockchain/evm/src/lib.rs:25–30` explicitly re-exports the codec from `outbe-primitives`. The selected P0 contract adds an optional post-boundary/post-hook application plus opt-in OART V0x0C (`design.md:183–204`), so codec/layout/phase/header-body binding and activation fixtures are a required seam, not an adjacent optional refactor. Existing OART V0x0B tags 0x01–0x08, retired 0x04 and independent record field are confirmed in `primitives/src/reshare_artifact.rs:53–109`; 64 KiB is `primitives/src/consensus.rs:26`, consensus n≤256 is `consensus/src/bls.rs:36`.

Required: correct the P3 actual file map and source matrix to the primitive-owned system-tx seam. Pin where the optional Radicle phase runs relative to hook execution and where OART activation/version selection is supplied to proposer, verifier and execution. Add concrete future tests for disabled-feature old format, active format, missing optional attestation, wrong activation/version, duplicate tag, header/body mismatch, combined DKG+late-finalize+CE-root budget, invalid attestation rejection and same-block membership transition. These remain planned production tests, not prerequisites to run during P0.
