Ack direction rules prevent a peer receiving V2 before it can decode it; unsupported BLS requests fail explicitly rather than downgrade.
- Commonware pin is `d476a2361ce6840d2b9d0aa6fb30a924429046d4` in both lock scopes. Actual threshold API accepts namespace/message; `union_unique` is the framing, MinSig public/signature sizes and DST match source, and G2 decoder rejects infinity/subgroup violations. Existing provider seed signer proves primitive capability, not an existing authorized arbitrary-message signer; P3 must add the typed fixed-domain policy interface without Share export or waiting under a consensus mutex.
- Current identity endorsements supplement genuine native threshold signatures; they do not replace repository authority with an aggregate. The node derives membership/index/material from authenticated state/output, not RPC/peer claims or ACTIVE alone. Per-entry receiver policy closes the raw old-owner-key and mixed-author-graph path. Historical receipts authenticate historical material; cached crypto validity alone does not create authoritative history.
- Deterministic preparation pins approved revision/prior owner tip/resource, ordered parents/trailers, metadata/time and owner refs. Witness subsets, new local author tips, Git configuration and later finality tips do not affect committed package/body. Actual threshold subsets012/123 produce the same native signature and the reduced staggered collector model reaches one checkpoint without the fourth participant. Existing native collaboration update uses local graph tips, so the new two-phase preparation seam remains necessary and is explicitly mapped.
- Review and Merge are separate native steps/checkpoints; TargetMoved requires another Vote/precondition; conflicts do not introduce new code/rebase/squash. Approval ordering is finalized height/proposalID. Before checkpoint a material change cancels/reprepares only unfinished jobs. After checkpoint durable exact package replay installs objects before refs, uses CAS/already-new idempotence, quarantines conflicts and marks durability before announcement. Late historical delivery and latest-snapshot installation do not allow rollback.
- OGD1 exact preimage contains known pre-genesis inputs only and is never rewritten to add its resulting genesis hash. Existing 64KiB/root/late-finalize/DKG rules are preserved.

After the potentially large activation artifact, the small mandatory summary/timestamp/late-finalize(K=3)/CE-root records leave ample static byte capacity for <4KiB batch; actual codec/assembly/gas confirmation remains an explicit P3 requirement. At n256/q171 each stage needs6 full batch slots; three ordered checkpoints need18. The count model completes at blocks13/26/38 in each of five periodic versions for300/30,300/200,1200/30 and65/1, with its documented busy/omitted blocks and finality/preparation waits. It also checks n4 and unsupported short windows. This fits even before the earliest allowed freeze, without depending on the exact freeze-boundary block.

The model does not pretend to measure real DKG/Git/sidecar timing or certify gas. Missed windows preserve approval/WaitingForWindow and reprepare next generation; completed Review resumes Merge. Thus the former deterministic capacity impossibility is resolved at P0, while future production timing/budget tests remain mandatory acceptance gates in their respective stages.
