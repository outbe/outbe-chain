## Genesis descriptor and trust argument

`design.md` §5 specifies `OGD1 || schema:u16 || chain_id:u64 || genesis_timestamp:u64 || length-prefixed fixed name/branch/description || initial_tree_oid[20] || content_manifest_sha256[32] || policy:u8 || key_source:u8`, in big endian. Text lengths are byte lengths and bounded; schema/policy/source, UTF-8, CR/NUL, truncation/trailing data, genesis timestamp and content commitments have explicit validation rules. The empty manifest is exact UTF-8 `[]` without LF and Git empty tree OID. SHA256 applies to exact OGD1 bytes without an added encoding layer.

All descriptor inputs exist before genesis allocation. Neither actual genesis hash, future RID/DKG key nor descriptor's own hash is a preimage input. Seeding stores descriptor/hash; later chain identity is never written back into the descriptor. Thus there is no fixed-point/self-reference requirement.

The subsequent fixed OPB1 includes actual chain/genesis, descriptor hash, RID, owner key, current material and initial manifest; handler requires its own actual chain identity and seeded descriptor. Same chain ID/descriptor on distinct genesis hashes therefore does not share publication authority. `descriptor_check.py` proves finite framing/hash separation, with dummy public material/manifest fixtures correctly labelled. It does not claim an actual authenticated DKG, identity signature, consensus-finality or production genesis run. Real MinPk message binding is independently exercised by the unchanged reduced publication model.

Reviewer independently parsed each OGD1 length/field, recomputed empty-tree SHA1 and manifest SHA256, recomputed descriptor hash, parsed OPB1 chain/genesis/RID/descriptor offsets, recomputed RID from fixture blob bytes and the full receipt hash. Result: PASS. Source `scripts/genesis_seed_alloc.py:94–106` confirms existing registry seeding only owns capacity slot5; append-only descriptor/checkpoint schema is explicitly new P4 work, not misrepresented existing storage.
