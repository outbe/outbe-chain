## Concrete contract and integration checks

The BLS ciphersuite is pinned Commonware MinSig (G2 key96/G1 signature48, POP DST), with `union_unique` and fixed `radicle.repository.bls.v1` namespace. MinPk consensus identities remain separate. Commonware threshold `sign_message`/`recover`, N3f1 and domain framing (C01–C06) plus `hybrid/vrf_material.rs:125` demonstrate the primitive/interface feasibility, while the future signer must enforce typed jobs/current material and never offer arbitrary namespace/message or Share export. Chosen-message security with disjoint domain inputs is the design assumption; tests alone are not presented as a cryptographic proof.

Current checkpoint authorization uses q current identity attestations over one deterministic body after complete native signatures and validated current indexed partial witnesses. Witness subsets are not hashed into the manifest. Job anchors and owner parents/refs are derived from exact approval/previous receipt/current binding, not local newest tips. This removes the subset/local-tip divergence that could occupy incompatible immutable slots. Reconstructed native metadata signs tree and all parent/author/committer/message bytes, including Resource/Related trailers.

Managed owner policy applies per entry before evaluation, including entries reached through an ordinary author namespace. Existing cache database getters can return materialized state without reevaluating the graph (`patch/cache.rs:457`), while no-cache calls store lookup (`:501`); both must apply receipt provenance/freshness. Local `Store::update` signs refs after COB update; the generic two-phase hook/journal contract covers both. Fetch validates identity/signed refs and later applies updates in `radicle-fetch/src/state.rs`; it cannot replace direct lookup/cache enforcement. These are explicit implementation obligations with adversarial scenarios in P2/P6/P8, not alleged existing production security.

The carrier contract fixes tag09/OART V0x0C, body477 + count1 + at most32 entries of index4+MinPkSig96: payload3678/framed3681. Strict sorted indices/count/length checks and all-entry validation precede state changes; invalid last entry rolls back whole batch, tally occurs once. Cap32 is independent of n≤256. Current `OutbeBlockArtifacts`, consensus64KiB cap, `system_tx/layout.rs:116`, phase and actual EVM configuration support an ancillary optional record, preserving DKG/root/late-finalize rules and never waiting on sidecars. Actual assembly, gas and atomic runtime tests remain required by P3.

Same-set periodic resharing is preserved. Effective `epochLength - min(prepare,epochLength) >=64` is feature-enabled validation, not a global cadence change. n256/q171 needs6 batch slots/checkpoint and18 for BindMaterial/Review/Merge. The schedule model exercises repeated generations and accepted/default/short windows, bounded delay and omissions; it explicitly assumes readiness/finality/delivery/fair inclusion. Missed windows retain approval and wait without extending stale rights or blocking consensus. Sources S41–S45 ground freeze/activation/persistence/effective timing; no unconditional liveness claim is inferred.

OGD1 excludes future genesis hash, RID, group key and self hash; descriptor hash `0349a0178f4f477562b46c3c9690408ff65cdeb41d059898d38b85791fa92bcf` is independently reconstructed. Bootstrap later binds actual genesis and derived native RID/key through current quorum OPB1. Reserved managed registration and exclusion from pre-bootstrap availability barriers address empty startup/ordinary-registration races.

Patch Vote cast/tally use the same target-specific ACTIVE∩effective electorate, preserving unrelated targets and existing yes*3≥count*2. Approved is immutable chain permission with no Git I/O. Review Accept precedes a separate Merge checkpoint. Exact revision/expected head are pinned; TargetMoved/conflict stays ApprovedUnmerged, with no rebase/squash or automatic code edits. Durable package-before-checkpoint, objects-before-CAS and marker-before-announcement ordering provides deterministic restart/idempotence and avoids equating Review with Merge.
