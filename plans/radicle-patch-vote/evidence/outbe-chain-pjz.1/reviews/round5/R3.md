### Genesis, current authority и history

Exact OGD1 preimage включает chain_id/timestamp, name/branch/description, initial tree/content commitments, schema/policy/key source; descriptor hash не зависит от будущих ключей/chain hash. Затем seeded genesis → actual genesis hash → authenticated DKG → canonical Doc/RID → finalized bootstrap checkpoint. Нет self-reference через Doc signature: Doc blob содержит authority key, signature находится в последующем operation tree; OPJ1 не включает собственную signature/manifest. Subject signing последовательно Doc → COB → refs → publication. Descriptor vector hash `0349a0178f4f477562b46c3c9690408ff65cdeb41d059898d38b85791fa92bcf`; OPB1 different-genesis receipt hashes отличаются. Эти fixtures не выполняют production genesis/DKG.

Current consensus includes lifecycle states, которые нельзя приравнять ACTIVE: source `queries.rs:125–130` прямо сохраняет Exiting/JailRetained до boundary. Design signer использует exact effective set, а patch electorate — ACTIVE∩effective при cast и tally с unchanged default targets. Existing Vote `runtime.rs:310,401–415` и `state.rs:144–150` дают concrete seams для target-specific extension; handler пишет bounded immutable authorization без Git/network. Proposal/patch/revision/precondition immutable, новый revision требует нового Vote; No-voter может исполнять Approved.

Constant owner key при reshare не считается криптографическим отзывом. Current quorum checkpoint является дополнительным guard, не заменой threshold signature. Before-checkpoint transition отменяет попытку; after-checkpoint exact package остаётся history. Trusted local finality и freshness — обязательная граница: isolated generic Heartwood не доказывает current-set permission. Для fresh/lagging receiver latest complete snapshot, reachable receipts и local CAS позволяют догнать состояние без ошибочного требования иметь global predecessor локально; same-sequence conflicts и rollback запрещены.

### Convergence, ordering и bounded execution

Witness bundles не входят в manifest/body; их q partials при этом проверяются. Native metadata/parents/resource/related и owner refs derive из approved pinned graph + accepted receipts, а не latest local graph/clock/tip. Anchor один job-derived canonical block. Два разных valid q-subsets и разные local tips поэтому не расходятся по body. Reduced model повторил staggered 2+2 schedule с checkpoint при q=3 без четвёртого участника; это ограниченная модель выбранного правила, не production convergence proof.

Review checkpoint и Merge checkpoint разделены. Native `patch.rs:1247–1306` требует delegate merge и branch ancestry для Merged, поэтому Review сам по себе недостаточен. TargetMoved требует нового Vote/precondition; conflict остаётся ApprovedUnmerged. Порядок approvals `(finalized height,proposalId)`. Journal persist complete package до attestation/checkpoint; objects install до refs CAS; complete sigrefs verification до promotion; durable marker до announce; replay already-new идемпотентен, divergent refs quarantined. После checkpoint пересоздание нового package запрещено.

Source `reshare_artifact.rs:54–92` показывает actual V0x0B/tags, retired04, root reservation и late-finalize K=3/bitmap32/sig96; `records.rs` показывает единственный consensus enum slot, который новый carrier не должен занять. Source `consensus.rs:26` ограничивает extra_data64KiB, `bls.rs:36` committee256. Design выбирает новый независимый tag09/V0x0C, 477-byte OPB1 body + count1 + ≤32*(index4+sig96): payload3678/framed3681. Все проверки до atomic effects, один tally, ≤32 verifications, ≤256 tagged pending slots. Absent mailbox не блокирует proposer; mandatory DKG/root/late-finalize не выбрасываются; неспособность вместить frame означает deferral.

Periodic same-membership reshare не отключён: `handoff.rs:34–36`, `freeze.rs:48–65`, `persistence.rs:259–270`, `activation.rs:117–129` действительно меняют epoch/material. Guard effective `L−min(P,L)≥64` при feature genesis/startup даёт выбранное pre-freeze окно. При n256/q171 нужны6 batch slots/checkpoint,18 для Bind→Review→Merge. Schedule model повторён на пяти generations, defaults300/30 и300/200, shortest65/1, bounded delays/omissions и invalid cadences. Это capacity при явно stated timely readiness/finality/delivery/fair inclusion, не arbitrary-delay liveness. Production codec/gas/readiness доказательства прямо обязательны P3/P6/P8; модель их не заменяет. Не найдено неизбежного startup/cadence deadlock в выбранном контракте.
